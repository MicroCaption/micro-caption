## 1. Session Goals

A re-prioritization session. Since the product captions **live** streams — which
are inherently delayed anyway — the top priorities are now, in order:
**accuracy → readability → in-sync-ness** of captions with the picture. Concretely:

1. Make **Parakeet** the primary ASR engine, with **Whisper** as a fallback that
   recovers automatically — Parakeet is faster and more accurate.
2. Hold the video behind live so captions can be laid out for readability **and**
   aligned to the picture (broadcast-style delay), revealing only once a caption
   cache exists.
3. Build out the stubbed **Logs** page into a real log manager.

## 2. Getting Parakeet Running In-Process on Python 3.14 (the hard part)

The plan assumed a **sidecar** because the project notes said NeMo "can't install
on Python 3.14." Testing proved that premise stale — but uncovered a *cascade* of
bleeding-edge blockers that took the bulk of the session to work through. The end
state is a clean **in-process** Parakeet (no sidecar):

- **pip can't resolve NeMo** (`resolution-too-deep`). **uv** resolves a clean
  wheel set (NeMo 2.7.3, onnx 1.22 abi3, numpy stays 2.x).
- A few C++ deps (e.g. `kaldialign`) have no cp314 wheel and fail to build against
  this box's **CMake 4.2** — fixed with `CMAKE_POLICY_VERSION_MINIMUM=3.5`.
- **GPU kernels:** the RTX 5070 Ti is Blackwell (sm_120). `torch cu126` has no
  sm_120 kernels; `cu130`'s cuDNN wheel is a **stub** (no `.so`). Landed on
  **`torch 2.11.0+cu128`** (Blackwell-capable).
- **cuDNN:** NVIDIA's PyPI cuDNN 9.19/9.20 wheels are **stubs with no libraries**.
  Vendored the real `cudnn-linux-x86_64-9.19.0.56_cuda12` from NVIDIA's redist into
  `server/vendor/cudnn/lib` (fetched by `server/vendor/fetch_cudnn.sh`, gitignored)
  and put it first on `LD_LIBRARY_PATH` in `run.sh`.
- **Model:** `nvidia/parakeet-tdt-0.6b-v2` (public). The configured
  `parakeet-tdt_ctc-0.6b` is gated (HF 401).

**Verified:** Whisper (ctranslate2) and Parakeet (torch + cuDNN 9.19) both run on
the GPU **in one process** under the production `LD_LIBRARY_PATH`; Parakeet word
timestamps work; ~8 GB VRAM steady-state with both models resident (expected). The
ASR-environment requirements are now documented in `CLAUDE.md` ("ASR Environment").

## 3. Supervised Dual-Backend (failover + auto-recovery)

`SharedASRBackend` (`server/microcaption/asr/pipeline.py`) was upgraded from
"pick one at load" to a **supervised pair**:

- Parakeet primary; Whisper **preloaded** as a hot standby (`asr.preload_fallback`).
- On a Parakeet error, the **same inference call is retried on Whisper** (no caption
  dropped), `_active` flips, and a background thread reloads Parakeet and **switches
  back** once a smoke-test inference passes (`recovery_interval_sec`).
- Inference calls never raise (safe-empty on a double failure) so the ASR worker
  thread can't die. `supports_words` stays `True` so the streaming pipeline never
  changes mode across a failover.
- `parakeet_backend.py` rewritten to load NeMo in-process with
  `transcribe_words()` matching the Whisper contract.
- New unit test `server/tests/test_shared_backend.py` (failover → retry-on-Whisper
  → auto-recovery). Full suite: **73 passing**.
- Config: `asr.primary: parakeet`, `preload_fallback: true`, `review_delay: 4.0`
  (accuracy-first, absorbed by the sync delay).

## 4. Phase-1 Broadcast-Style Video↔Caption Sync

Video and captions had **no shared clock** (the browser plays an independent
YouTube iframe; the server pulls audio separately). Phase 1 (best-effort, tunable;
frame-accuracy deferred to a Phase-2 server-owned timeline):

- **Server:** `GET /api/session/<id>/sync` (join epoch, newest caption time, sync
  config) + `YouTubeAdapter.start_epoch`; new `sync:` config
  (`target_delay_sec: 20`, `min_cache_sec`, `offset_nudge_sec`).
- **Client (`captions.js`):** `CaptionPacer` gained a **timeline-driven scheduled
  mode** — blocks are tagged with their stream-time onset and shown when the
  (delayed) video playhead reaches them (`tick(streamTime)`), with catch-up
  dropping disabled (the delay buffer gives all the slack we need). Live reading-
  paced mode kept for the caption-only viewer.
- **Client (`player.js`):** calibration → "Aligning captions… %" cache-then-reveal
  → seek the video `target_delay` behind live → drive captions off the video clock.
  `[` / `]` keys nudge alignment live.

**Bug found & fixed:** captions were ~8 s late. The reveal anchored the video's
live edge to `stream_clock_now` (newest *committed caption*), which trails the
audio by the whole pipeline latency (`review_delay` + LocalAgreement + pacing).
Re-anchored to the **live audio ingestion time** (`server_now − join_epoch`),
removing the systematic ~8 s shift. Any residual is the iframe-vs-server latency
difference, tuned by the nudge.

## 5. Logs Page → Heroic-Style Log Manager

Rebuilt the stub `Logs` page (`client/logs.html` + new `client/js/logs.js`) into a
two-pane manager: a sources **sidebar** (System logs · Live streams · Stream
history) and a **viewer** pane.

- **Server endpoints** (auth-gated, whitelisted — no arbitrary paths):
  `/api/logs/sources`, `/api/logs/file/<id>?tail=N` (efficient tail even on the
  39 MB packet logs), `/api/logs/session/<id>` (live from the writer, else the
  archive file). New `server/microcaption/output/session_archive.py`.
- **Caption history:** timestamped transcript (`mm:ss → text`, speaker labels where
  present), accuracy/WER bar for older archives, Copy transcript / Download `.vtt` /
  WebVTT link.
- **Persistence:** sessions are now **archived on stop** to
  `logs/sessions/<id>.json` + `index.json`, so streams appear under History after
  they end. `run.sh` and `serve.py` now mirror output to `logs/server.log` /
  `logs/client.log` so the System log entries populate.

> Caveat: WER/speaker enrichment in new archives isn't wired into today's stop path
> (it came from an earlier accuracy/diarization pipeline); new archives store plain
> cues. Existing rich archives are unchanged.
