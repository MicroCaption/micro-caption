## 1. Session Goals

Started as a strategy question — *can the new accuracy checker be used to improve
the model itself?* — and turned into building the next captioning-standard
requirement: **speaker identification** (who is speaking, marked in the captions).

Two threads:

1. **Model improvement (discussion → deferred).** Confirmed the verifier's
   "reference" is Whisper transcribing itself at beam 5, **not ground truth** — so
   training on it would just distil the model's own errors. The accuracy checker's
   real value is as an **eval harness + worst-segment triage**, not training labels.
   Agreed near-term wins are **`initial_prompt`/hotwords** (council names, agenda
   terms) and an expanded **deterministic corrector glossary**, with optional LoRA
   fine-tuning only once a *human-corrected* corpus exists. Logged for a later
   session; UIs for hotwords/corrector to follow.

2. **Speaker notation (built this session).** Per the CEA-608/708 convention:
   `>>` at a speaker change, and named/numbered speaker labels. Decisions taken
   with the user up front:
   - **Anonymous numbered** — `>> SPEAKER 1:`, `>> SPEAKER 2:` via online
     clustering. No voiceprint enrollment (named identity can layer on later).
   - **Hybrid placement** — `>>` change marks **live** (best-effort); stable
     `SPEAKER N` numbering resolved by a **second pass behind live**, mirroring the
     accuracy verifier's architecture.
   - **Non-NeMo stack** — avoid NeMo (still blocked on Python 3.14 wheels).

## 2. The Dependency Journey (the substance of the session)

The diarization *logic* was straightforward; making the **speaker-embedding model
actually runnable on Python 3.14** was the real work, and it moved three times:

1. **Plan said "ONNX, not torch."** SpeechBrain/pyannote embedders hard-depend on
   PyTorch, and the box is **Python 3.14.4** — the same wheel gap that blocks
   NeMo/Parakeet. A first-principles plan led to an ONNX-Runtime embedder to keep
   torch off the critical path.

2. **First cut: raw `onnxruntime` + a librosa fbank.** Worked, but the WeSpeaker /
   3D-Speaker models are trained on **kaldi-style fbank**, which librosa's log-mel
   doesn't match exactly — embeddings would be self-consistent but mis-calibrated.
   Flagged as needing on-machine validation.

3. **Found the right tool: `sherpa-onnx` (k2-fsa).** It hosts ready-made ONNX
   speaker models **and** computes the correct kaldi-fbank front end internally —
   and, critically, **ships a cp314 wheel** (`sherpa_onnx-1.13.3-cp314`, verified
   installable + a real 256-dim embedding produced from the real model). Rewired
   `SpeakerEmbedder` to sherpa-onnx behind the **same `embed()` interface**, so the
   change detector, clusterer, second pass, and every test were untouched. The
   feature-matching problem disappeared.

**Net:** speaker embeddings run on Python 3.14 with **no PyTorch**, no NeMo, and no
hand-rolled DSP.

## 3. What Was Built

### 3.1 New module — `server/microcaption/diarize/`
- **`embedder.py`** — `SpeakerEmbedder`: sherpa-onnx speaker model, shared across
  sessions, lock-serialised `embed()`. **Graceful degrade is a hard requirement:**
  if sherpa-onnx or the model can't load, `available = False` and the whole layer
  no-ops — the caption pipeline is byte-for-byte unchanged. Cosine helpers live here.
- **`change.py`** — `SpeakerChangeDetector` (live): one embedding per utterance vs
  the previous → cosine distance over `change_threshold` flags a turn (`>>`).
  Skips sub-`min_utterance_seconds` clips (roll-call "Aye"/"Nay") so they don't
  pollute the reference.
- **`clusterer.py`** — `OnlineSpeakerClusterer` (behind live): nearest-centroid
  assignment with running-mean centroids; labels handed out in first-appearance
  order and **never renumbered** (SPEAKER 1 stays SPEAKER 1 when a voice returns).
- **`second_pass.py`** — `DiarizationPass`: sibling of `AccuracyVerifier`. Buffers
  the same audio, groups committed cues into utterances (by inter-cue gap), embeds
  each, clusters, and emits `[{start, speaker}]` updates. **Source of truth** for
  who-spoke labels; live `>>` is best-effort.

### 3.2 Threaded a speaker field through the existing path
- **`asr/pipeline.py`** — `CaptionResult.speaker_change`; an optional
  `speaker_change_fn` hook called on the **first emit of each utterance** (embeds
  `buf` before it's trimmed) so the `>>` lands at the turn start, not a step late.
- **`caption/normalizer.py`** — `speaker_marker()` / `apply_speaker_marker()`
  (`>> ` live, `>> SPEAKER N: ` once labelled); first-line-only, non-mutating.
- **`caption/webvtt.py`** — cue dict gains `speaker` / `speaker_change`; new
  `set_cue_speaker(start, label)` for the behind-live relabel.
- **`output/webvtt_server.py`** — `on_caption(..., speaker_change)`; new
  `event: speaker` SSE for relabels; `push_cue` generalised to `push_event`.
- **`main.py`** — bakes the `>>` mark into the CEA-608/708 byte stream
  (`>` = `0x3E`, valid odd parity — confirmed), wires a shared `SpeakerEmbedder`,
  per-session live detector, and `DiarizationPass` (audio fan-out + relabel
  callback + lifecycle stop). **Off unless `diarize.enabled`.**
- **`session.py`** — `Session.diarizer` lifecycle field.
- **Client** — `player.js` renders live `>>` and replay `SPEAKER N:` labels and
  handles the `speaker` relabel event; `watch.js` renders the live `>>`.

### 3.3 Config, deps, tooling
- **`settings.yaml`** — `diarize:` block (model path, device, thresholds, settle).
- **`requirements.txt`** — `sherpa-onnx` added.
- **`tools/validate_diarization.py`** — prints a pairwise cosine matrix over audio
  clips, to confirm the model works and pick thresholds before a live run.
- **`.gitignore`** — `server/models/` and `*.onnx` (model binaries not committed).

## 4. Contract: live vs. second pass

- **Live stream** shows only the best-effort `>>` turn mark (cheap; one embedding
  per utterance at first emit). The live roll-up is **not** retroactively edited.
- **Stored cues / replay / archive** are the source of truth: the behind-live pass
  writes stable `SPEAKER N` labels onto cues and pushes a `speaker` SSE event;
  replay reads labels straight from the persisted cue JSON.

## 7. Open Items / Notes

- **Thresholds need real-audio tuning.** Defaults (`change_threshold 0.55`,
  `cluster_threshold 0.45`) are starting points. VoxCeleb models are trained on
  cleaner speech than far-field city-hall rooms, so expect **change detection to be
  the reliable part** and exact `SPEAKER N` numbering to be noisier until tuned —
  that's what `validate_diarization.py` is for.
- **GPU budget.** Embedding is per-utterance and defaults to **CPU** (`device: cpu`)
  to stay off the shared Whisper lock; flip to `cuda` only if CPU can't keep up.
- **Overlapping speech / very short turns** aren't modelled (one embedding per
  utterance); single-speaker-per-utterance is assumed.
- **Named speakers (future).** Anonymous numbering is in; named labels
  ("MAYOR JONES:") would add a small **enrollment** step (voiceprint per council
  member, closed-set cosine match) on top of the same embedder — a natural next
  layer, pairs well with the planned hotwords UI.
- **Model-improvement thread (deferred).** Implement `initial_prompt`/hotwords in
  `whisper_backend.py` + a corrector glossary first; revisit fine-tuning only with
  a human-corrected corpus. The verifier is the eval harness for any such change.
