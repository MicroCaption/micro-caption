## 1. Session Goals

Two related asks: make the captioning **prioritise accuracy at all times** (it was
rushing and skipping words to stay near live), and build the **per-stream logs**
into something real — a list of streams, each with an **accuracy summary**, backed
by a **second "verifier" pass** that re-transcribes the audio and scores how well
the live captions matched. Logs must **persist across restarts** (last ~20 streams).

Landed on `feat/adding-logger-and-accuracy-checker`, commit `049596f`.

Confirmed up front with the user:
1. **Accuracy first** — never drop audio/words; captions may lag ~3–6 s.
2. **Record & verify behind live** — the verifier consumes the same audio at its
   own pace; never drops.
3. **Careful pass = reference** — no external ground truth; accuracy = how closely
   live deviates from the high-accuracy pass (WER → accuracy %).

## 2. Why Captions Rushed / Skipped Words

Both sides traded completeness for low latency:

- **Server dropped audio** under GPU lag — `ASRPipeline.on_audio()` did
  `put_nowait` then `except queue.Full: pass`. Dropped audio = permanently missing
  words.
- **Client rushed text** — `CaptionPacer` dropped queued blocks and collapsed
  display time to `minDwell` whenever it fell >2 s behind live.

The fix was to reverse both, accepting a few seconds of lag.

## 3. What Was Built

### 3.1 Accuracy-first behaviour
- **`server/microcaption/asr/pipeline.py`** — audio queue is now a deep,
  configurable bounded queue; `on_audio()` **blocks briefly instead of dropping**,
  and counts + loudly logs genuine overload (`dropped_chunks`, surfaced in
  `/api/metrics` as `dropped_audio_chunks`).
- **`settings.yaml` / `settings.prod.yaml`** — `review_delay` 2.5 → 3.5 (more
  look-ahead before committing words); added `audio_queue_max: 600`.
- **`client/js/captions.js`** — `CaptionPacer` **never drops blocks** and
  compresses dwell *gently* toward a readable floor (1500 ms) instead of flashing;
  the stream simply trails a few seconds behind live. Removed `maxBacklog`
  (and its use in `watch.js`).

### 3.2 Dual-pass accuracy verifier — `server/microcaption/accuracy/verifier.py`
- A per-session pass re-transcribes the same audio at **beam 5**, reusing the one
  shared GPU model (no second model loaded; serialised by the existing lock).
- Emits per-segment comparison records (reference vs live, WER, S/D/I) plus a
  rolling stream summary. See §4 for the alignment work that made the numbers
  honest.
- **`whisper_backend.py`** `transcribe_words` gained an optional `beam_size`;
  **`pipeline.py`** `SharedASRBackend.transcribe_words` forwards decode options.

### 3.3 Persistence — `server/microcaption/accuracy/store.py`
- `SessionStore` writes per-stream JSON + an `index.json`, keeps the most recent
  `retain_sessions` (20) streams, prunes older, and **reloads on startup** so past
  streams survive a restart. Atomic writes; throttled checkpoints; finalised on
  session end.

### 3.4 API + UI
- New routes **`GET /api/logs/sessions`** and **`GET /api/logs/session/<id>`**
  (`webvtt_server.py`), wired through provider closures in `main.py` that merge
  live sessions with persisted history.
- **`client/logs.html`** rewritten as a Heroic-style **two-pane** view: stream list
  with accuracy badges on the left; summary card + reference-vs-live segment
  comparison log on the right.

### 3.5 Reuse
- WER core factored out of `tools/validate_wer.py` into
  **`server/microcaption/text/wer.py`** (the CLI now imports it; the verifier uses
  the same scoring).

## 4. Getting the Accuracy Number Honest — Four Iterations

The verifier was built, but the **headline number was wrong** four different ways
before it was right. This is the substance of the session and worth recording.

1. **Blank page — a real bug.** `WhisperBackend.transcribe_words` returns
   `(word, start, end)`; the verifier joined element `[2]` (the end *timestamp*),
   so every verification threw `TypeError: expected str, got numpy.float64` and
   produced **zero records**. After ~7 min of a live stream the page still read
   `accuracy: null`. Fix: join `[0]` (the word text). A regression test was added
   — the original tests only exercised a text-only fake backend, so they missed it.

2. **~57 % — scored too early.** Once populating, accuracy read low because the
   verifier scored a window before the **live path** (which commits with a ~3.5 s
   review look-ahead) had emitted that window's tail. Correct-but-*late* captions
   counted as **deletions**. Fix: a **settle delay** — transcribe the reference
   promptly, defer scoring until the live side catches up.

3. **~83 % — boundary double-counting.** Consecutive verifier windows overlapped
   by 1 s of context, so words at the seam were counted in two windows
   (inflated **insertions**). First fix: partition time so each word/cue lands in
   exactly one window, and compute the **headline from a single alignment of the
   whole reference vs the whole live transcript** over a rolling span (per-window
   boundary effects cancel). This got the number to ~96 % but the per-segment
   **rows were still visibly misaligned** in the UI.

4. **Phase offset between columns — the real "weirdness" the user spotted.** The
   beam-5 reference and beam-1 live passes estimate word timestamps slightly
   differently, so binning **each side by its own timestamps** put the same words
   in different rows (a consistent 2–4 word shift). Fix (the verifier's current
   design): the **live captions define each segment** — group consecutive live cues
   into ~8 s spans, then **slice the verifier's retained audio to that exact span**
   and transcribe it for the reference. Both columns now cover the *identical*
   `[t0, t1]` and the *identical* live words; no independent time-binning to drift.

**Result:** rows correspond word-for-word, per-segment accuracy is ~1.0 where the
captions match, and the headline reads an honest **98–99 %**. The remaining gap is
genuine — an occasional dropped filler word (`um`, `wow`) and minor beam-1-vs-beam-5
differences — not a measurement artifact.

> Architecture note: the verifier keeps a rolling ~60 s absolute-time-indexed audio
> buffer. It groups live cues (closing a group only once a following cue confirms
> the boundary), slices `[t0 − pad, t1 + pad]` for decode context, runs beam 5, then
> trims the reference back to words starting in `[t0, t1)`.

## 6. Incident Note — Server Restart Churn (again)

Each verifier fix required a server restart, which interrupts the live stream.
This repeated Session 7's lesson and added one:

- Long-lived processes were launched via the **harness-tracked background mode**
  (not shell `&`) so they persist — that part went smoothly this time.
- Restarting to load a fix **kills the user's running stream.** Each time, the same
  YouTube URL was **re-submitted via `POST /api/start`** so the session came back
  and the new code could be verified immediately. The Logs list therefore shows
  several `ended` test sessions from the iterations (retention keeps the last 20);
  they're harmless and visibly chart the accuracy climbing 81 % → 93 % → 96 % →
  98–99 % as each fix landed.

**Lesson:** before restarting to reload code, check whether a running server is
serving the user's session; if so, plan to resubmit it afterward.

## 7. How to Resume / Restart

```bash
# Caption API server (live Whisper ASR; verifier auto-starts per session)
cd /home/joe/Development/micro-caption
./server/run.sh

# Client static app (separate process)
cd client && python3 serve.py        # http://localhost:3000

# Logs page:  http://localhost:3000/logs   (or via the funnel /logs)
```

Verifier / persistence tuning (`server/config/settings.yaml`):

```yaml
asr:
  review_delay: 3.5          # accuracy-first look-ahead
  audio_queue_max: 600       # never drop audio under transient GPU stalls
  verifier:
    enabled: true
    beam_size: 5             # thorough reference decode (live stays beam 1)
    settle_seconds: 5.0      # let live commit before scoring
    headline_seconds: 600.0  # rolling span for the headline alignment
    segment_seconds: 8.0     # target comparison-row length
accuracy:
  log_dir: logs/sessions     # gitignored; per-stream JSON + index.json
  retain_sessions: 20
```

## 8. Open Items / Notes

- **GPU budget.** The verifier adds a beam-5 decode per stream, sharing the one
  model under the same lock as the live path — fine for a single stream, watch
  `dropped_audio_chunks` (pipeline) and `skipped_segments` (verifier) under
  many concurrent streams.
- **Accuracy is relative.** "99 %" means *live agrees with the careful pass 99 %*,
  not absolute truth — the right proxy given no ground truth on live streams.
  Disfluencies the careful pass keeps but live drops (and vice versa) are real,
  small, residual differences; don't expect a literal 100 %.
