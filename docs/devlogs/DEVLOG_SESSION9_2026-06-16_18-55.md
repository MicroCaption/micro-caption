## 1. Session Goals

A short session that started as "spin up the app for live testing" and turned into
a **scope pivot**. The product's normal working scope is no longer YouTube videos —
it is a **broadcast inline pass-through captioner**:

- **Ingest:** an encoder **pushes RTMP** to us, *or* we take an **SDI** signal in.
- **Egress:** we send the captioned signal back out as **RTMP or SDI** (corresponding),
  with the CEA-608/708 captions **embedded** in the outgoing stream.

YouTube was only ever a convenient dev source. The goal this session was to (a) get
RTMP ingest working enough to test, and (b) lay out the staged plan to the full
in→caption→out path.

---

## 2. Reality Check — What the Codebase Actually Supported

Before writing anything, mapped the current architecture against the new scope:

- **Adapter selection was a no-op.** `start_session()` computed
  `source_type = 'youtube' if video_id else 'stream'` but `_launch()` then built a
  `YouTubeAdapter` **unconditionally** — the `'stream'` branch was stubbed and never
  wired.
- **The YouTube adapter can't carry RTMP** even if selected: it runs `yt-dlp -g` to
  resolve a CDN URL, then feeds it to GStreamer **`souphttpsrc`** (HTTP-only). yt-dlp
  doesn't speak `rtmp://`, and `souphttpsrc` can't read it.
- **No video plane, no egress.** `InputOutputManager` (`io/base.py`) is **audio-IN
  only** (`set_audio_callback`, `sample_rate`). The 608/708 packetizers produce correct
  bytes but they go **only to `PacketLogger` + WebVTT/SSE** — nothing embeds them into
  an outgoing signal. `DeckLinkAdapter` is still a `NotImplementedError` stub.

**Conclusion:** the current system is an *audio-in → caption-monitor* tool. The new
scope (inline pass-through captioner) is a different class of system. Good news: this
box's GStreamer has every element needed — `rtmp2src`, `rtmpsrc`, `rtmpsink`,
`flvmux`, `x264enc`, the `closedcaption` plugin, `decklinkvideosink`,
`srtsrc`/`srtserversink` — and the hard part (byte-accurate 608/708 generation) is done.

## 4. Stage A — `StreamAdapter` (implemented)

New `server/microcaption/io/stream_adapter.py`:

- Reads live-stream URLs **directly via GStreamer `uridecodebin`** — **no yt-dlp**
  resolve step. Claims schemes `rtmp://`, `rtmps://`, `rtsp://`, `srt://` via a
  `StreamAdapter.handles(url)` classmethod.
- Programmatic **dynamic-pad linking** (not a `parse_launch` one-liner): a muxed A/V
  stream exposes both audio and video pads — audio links to the ASR branch
  (`audioconvert → audioresample → F32LE/16k/mono → appsink`), video/other pads are
  drained to a `fakesink` so the demuxer doesn't stall on an unlinked branch.
- Same audio output contract (16 kHz F32LE mono `AudioChunk`) and `start_epoch` /
  end-callback semantics as `YouTubeAdapter`, so it drops straight into the existing
  `ASRPipeline`.
- `is-live` handling left to `uridecodebin` (`use-buffering=False` for low latency).
- **Stage-A scope: monitor only.** Video is decoded and discarded; no egress yet.

Wiring:

- `main.py` `_launch()` now **dispatches on URL scheme** —
  `if StreamAdapter.handles(url): StreamAdapter(...)` else `YouTubeAdapter(...)`.
- Registered in the `io/__init__.py` factory as `adapter='stream'` (valid set is now
  `alsa, youtube, decklink, stream`).

## 6. Open Items / Next

- **No RTMP ingest server on the box** (no mediamtx / ffmpeg / nginx). The Stage-A
  adapter is a **pull client**; the production workflow is **push**, so there's nothing
  for the encoder to push to yet. Next step is **Stage B**: stand up **MediaMTX** (single
  static binary) so the encoder pushes to `rtmp://this-box:1935/live/x` and the adapter
  pulls from `rtmp://localhost:1935/live/x`.
- **Plan Stage C** (egress + embedding) — it reshapes the I/O abstraction: a video
  plane, a real output sink, and frame-accurate caption-meta insertion. This is the
  heart of the new scope and the next design task.
- Stage-A `uridecodebin` decodes video only to discard it; once Stage C needs the video
  for pass-through this is no longer wasted, but until then it's avoidable overhead.
