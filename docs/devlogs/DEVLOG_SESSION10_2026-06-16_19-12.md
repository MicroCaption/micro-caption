## 2. Reality Check — DeckLink Card vs. Driver

Probed the box before writing anything:

- **Card is physically present:** `lspci` → `05:00.0 Blackmagic Design DeckLink Duo 2`.
- **But no driver is bound:** `lspci -k` shows no `Kernel driver in use`, there's no
  `blackmagic` kernel module, no `/dev/blackmagic*`, no `libDeckLinkAPI.so`, and no
  `desktopvideo` apt package. **Blackmagic Desktop Video is not installed.**
- **GStreamer side is ready:** `libgstdecklink.so` is present with `decklinkvideosrc`,
  `decklinkaudiosrc`, `decklinkvideosink`, `decklinkdeviceprovider`. But
  `gst-device-monitor-1.0` enumerates **zero** DeckLink devices — because the elements
  need the Desktop Video runtime + kernel driver to talk to the card.
- **Caption-embedding building blocks exist** (important for Stage 3): `cccombiner`,
  `ccconverter`, `cea608mux`, and crucially `decklinkvideosink` exposes a **`cc-line`**
  property (writes CC into VANC) and a **`profile`** enum that configures **Duo 2
  per-sub-device duplex** — exactly what an in→out loop on one card needs.

**Conclusion:** the only blocker to live SDI is the **Desktop Video driver**, which is
the user's to install (needs sudo + reboot, and a DKMS build against the very new
**kernel 7.0.0** — the main risk). Everything else can be built now and will light up
the moment the card enumerates.

## 4. What Was Implemented

### Stage 1 — enumeration, status API, UI
- **`server/microcaption/io/decklink_devices.py`** *(new)* — `list_devices()` (via
  `Gst.DeviceMonitor` over `Video/Source` + `Audio/Source` + `Video/Sink`, filtered to
  decklink; yields `{index, label, connection, can_input, can_output}`) and a cached
  `device_status(index)` that briefly prerolls `decklinkvideosrc` to detect SDI lock +
  mode. **Never raises** — empty list / `None` status when the driver is absent.
- **`GET /api/sdi/devices`** in `webvtt_server.py` — merges device list with live
  `signal_locked`/`mode` and which session currently owns each sub-device.
- **Dashboard UI** — `dashboard.html` / `dashboard.js` / `shared.css`: a URL|SDI source
  toggle, an SDI device `<select>`, an `SDI` session badge, and a **connector status
  strip** (green = signal, red = no-signal, amber blink = captioning) polled every 3 s.

### Stage 2 — SDI input adapter
- **`server/microcaption/io/decklink_adapter.py`** — replaced the `NotImplementedError`
  stub with a real `DeckLinkAdapter` modeled on `StreamAdapter`:
  `decklinkvideosrc → fakesink` (SDI lock + drain) **+** `decklinkaudiosrc
  connection=embedded → audioconvert → audioresample → F32LE/16k/mono → appsink`. Same
  `AudioChunk` / `start_epoch` / end-callback contract as the other adapters;
  `no-signal` element messages surface as a clean session error.
- **`main.py`** — `DeckLinkAdapter.handles('sdi://N')` dispatch; `source_type='sdi'`.
- **`config/settings.yaml`** — fleshed-out `io.decklink` block (`device_index`,
  `output_index`, `profile`, `caption_delay_ms` — the last two for Stage 3).
- **`session.py`** — `source_type` doc now includes `'sdi'`.

## 6. Next Steps (resume here after install + reboot)

**Step 0 — install the driver (user, with sudo; reboot after):**
1. Download "Desktop Video" for Linux from Blackmagic support (a `.tar.gz` of `.deb`s).
2. `sudo dpkg -i desktopvideo_*.deb` then `sudo apt -f install`.
3. **Watch the DKMS build against kernel 7.0.0** — primary risk. On failure, grab
   `/var/lib/dkms/blackmagic*/build/make.log` for diagnosis.
4. `sudo modprobe blackmagic`, then **reboot**.
5. (Optional) `BlackmagicFirmwareUpdater status`.

**Verification gate (must pass before continuing):**
```
lspci -k -s 05:00.0                 # want: Kernel driver in use: blackmagic
ls /dev/blackmagic/*                # device nodes exist
ldconfig -p | grep DeckLinkAPI      # runtime present
gst-device-monitor-1.0 Video/Source:decklink Audio/Source:decklink   # lists sub-devices
curl -s localhost:8765/api/sdi/devices   # now returns real connectors
```

**Step 1 — verify Stages 1–2 live:** open the dashboard, switch to **SDI**, confirm the
status strip flips green/red as a cable is plugged/pulled, then start `sdi://<i>` and
confirm **real captions** in the player (live ASR — never `--mock-asr`).

**Step 2 — build Stage 3 (output passthrough + VANC):**
- Configure Duo 2 `profile`/duplex so a chosen connector pair runs input + output
  simultaneously (confirm grouping against the physical wiring).
- Bridge ASR captions into GStreamer CC: reuse `DTVCC708Packetizer` → `appsrc`
  (`closedcaption/x-cea-708`) → `cccombiner` → `decklinkvideosink cc-line=<N>`;
  `ccconverter` adapts format/framerate.
- Delay passthrough **video** by `io.decklink.caption_delay_ms` (~3 s) to align with
  caption latency.
- Validate with a loopback (SDI out → second SDI in) + `ccextractor`/`line21decoder`.
