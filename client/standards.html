Standards & compliance

Broadcast and accessibility standards

MicroCaption is built against the standards used in professional broadcast and web accessibility. The table below lists each relevant specification, its implementation status in the current release, and any important caveats.

Implemented Partial / conditional Planned
CEA-608-E / EIA-608 — Line 21 Closed Captioning Implemented
The original analogue closed-captioning standard, carried as Line 21 VBI data in NTSC broadcasts. MicroCaption generates byte-accurate CEA-608 character pairs with correct odd parity, roll-up channel assignments, and null-pair padding to the 29.97 fps frame rate. Output is suitable for insertion into SDI ancillary data (VANC line 21 emulation) or multiplexing into MPEG-2 user data.
CTA-708-E / CEA-708 — Digital Television Closed Captioning Implemented
The successor standard for digital (ATSC/cable) television. MicroCaption produces DTVCC Transport Layer packets containing Service Block data for Service 1 (primary English). cc_data tuples are constructed per the CTA-708-E spec and are ready for embedding in MPEG-2 SEI or H.264/H.265 user-data payloads. CEA-608 compatibility bytes are included in every packet for legacy decoder fallback.
W3C WebVTT — Web Video Text Tracks Implemented
MicroCaption writes a live WebVTT stream for each session, delivered to browsers via Server-Sent Events and available as a downloadable .vtt file. Cue timing follows the WebVTT 1.0 W3C Recommendation. WebVTT files can be attached directly to HTML5 <video> track elements or ingested by most NLE and captioning workflows.
FCC 47 CFR Part 79 — Closed Captioning of Video Programming Partial
Part 79 requires video programming distributors to pass through closed captions and sets quality standards (accuracy, synchronisation, completeness, placement). MicroCaption addresses the technical packet layer (CEA-608 / CEA-708 output) and targets sub-2-second caption latency. Compliance with all Part 79 quality benchmarks depends on ASR accuracy for your specific programme content and language, which varies. Full end-to-end compliance assessment is the operator’s responsibility.
WCAG 2.1 SC 1.2.2 — Captions (Pre-recorded) — Level A Via WebVTT
SC 1.2.2 requires captions for all pre-recorded audio content in synchronised media. MicroCaption’s WebVTT output can satisfy this criterion when applied to recorded streams. Caption accuracy must meet the “equivalent” threshold; post-processing review is recommended for pre-recorded content where accuracy requirements are strict.
WCAG 2.1 SC 1.2.4 — Captions (Live) — Level AA Implemented
SC 1.2.4 requires captions for all live audio content in synchronised media. This is MicroCaption’s primary design target. Live WebVTT delivery via SSE and real-time CEA-708 packet generation both address this criterion. Note that WCAG acknowledges live ASR captions will not achieve the same accuracy as human stenographers; the standard permits reasonable best-effort for live content.
SMPTE ST 2038 — Carriage of CEA-708 in SMPTE ST 2110 Planned
ST 2038 defines how to carry ancillary (ANC) data — including CEA-708 caption packets — over IP media networks conforming to SMPTE ST 2110. Support for SMPTE 2110 ANC output is planned for a future phase once the DeckLink SDI interface (Phase 2) is integrated.
ATSC A/72 — Captions in ATSC 3.0 (NEXTGEN TV) Planned
A/72 defines closed-caption delivery for ATSC 3.0 broadcasts using IMSC 1.1 (a profile of TTML). As ATSC 3.0 rollout continues in the US and internationally, MicroCaption will add TTML/IMSC output alongside the existing CEA-608/708 and WebVTT tracks.
